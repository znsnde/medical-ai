## 1. 开场（1 分钟）：一句话项目定位

> 这是一个面向医疗场景的 **AI 辅助诊断平台**——医生录入病历和影像，系统自动结构化、结合医学知识图谱与临床指南 RAG 给出诊断建议；同时提供患者自助查看报告、医学文献速读等完整闭环。

技术栈一句话带过：**FastAPI + Vue 3**，底层 **MySQL + Neo4j + Milvus + DeepSeek 大模型**。

---

## 2. 主线一：AI 诊断流程（3 分钟）⭐ 核心演示

### 2.1 病历智能结构化（30 秒）
- 演示：医生端 → 新增病历 → 输入文本病历（或用自带 DICOM 影像）。
- 讲：LLM 把自然语言病历抽取为 **症状/既往史/诊断/用药** 结构化 JSON；LLM 不可用时自动降级为关键词规则抽取，主流程不中断。

### 2.2 AI 辅助诊断（2 分钟）⭐
- 演示：病历结构化后 → 点"AI 生成诊断"。
- 讲：**三级信息同时注入诊断建议**——
  1. **RAG**：病历向量化 → 从 Milvus 召回相似临床指南（18 条，如高血压指南）
  2. **知识图谱**：从 Neo4j 拉取关联疾病的 症状/用药/科室/并发症/相互作用
  3. **影像分析**：DICOM 元数据 + 像素 HU 统计 → LLM 生成影像解读
- 强调：诊断报告可导出 **PDF**（中医字体 UnicodeCIDFont 兜底）。

### 2.3 知识图谱可视化（30 秒）
- 演示：知识图谱页 → 搜索"高血压" → 子图展开，看症状/药物/并发症关系。
- 讲：ECharts 力导向图，按节点类型着色、悬停高亮、支持日夜主题。

---

## 3. 主线二：医疗 AI 的工程化（2 分钟）⭐ 加分项

### 3.1 多模态与降级（1 分钟）
- 讲：**任何一层不可用都不阻塞主流程**——RAG 挂了用图谱，图谱挂了用纯 LLM，LLM 挂了用关键词规则。影像无像素数据时诚实声明"仅基础信息描述"，不编造结论。

### 3.2 患者自助查看报告（1 分钟）⭐ 安全亮点
- 演示：切到患者端 → 登录 `patient_demo` → 我的病历 → **绑定手机号 `13800001111`** → 看到病历 + 诊断报告 + **下载本人 PDF**。
- 讲：数据按归属隔离——患者只能通过手机号认领**本人**档案；PDF 下载经 `report → record → patient.user_id` **三级归属校验**，未绑定/他人/匿名一律 403/401。

---

## 4. 主线三：安全与 CI（2 分钟）⭐ 硬实力

### 4.1 安全设计（1 分钟）
- 静态目录不再公开挂载：上传的 DICOM/报告 PDF 只能经**带鉴权下载接口**访问。
- 越权封堵：参考影像/问诊会话归属校验，患者不可读任意病历。
- JWT 独立密钥 + CORS 白名单 + 全局异常统一包装 + **审计日志**（登录/用户管理/诊断），**系统设置页可直接查询**，支持按级别/关键字筛选与分页。
- 登录防爆破 + 上传后缀白名单 + 文件名清洗。
- 软删除 + 回收站：患者/病历/报告删除先进回收站（`is_deleted` 标记，文件保留），支持**级联恢复**与**彻底删除**（purge 清行 + 清文件），误删可救。

### 4.2 CI 流水线（1 分钟）⭐
- 讲：GitHub Actions **三阶段**——
  1. 后端测试（拉起 MySQL 8 + Neo4j 5 服务容器，跑 54 项 pytest）
  2. 前端构建（Vite + nginx）
  3. Docker Compose 配置校验
- 强调：每次 push 自动验证，测试失败以 `::error::` 注释标注在 PR 上。**"提交即验证"**。

---

## 5. 收尾（1 分钟）：项目亮点三句

1. **三级辅助决策**：RAG 指南 + 知识图谱 + 影像分析同时注入诊断建议，且逐层可降级。
2. **患者数据按归属隔离**：自助查看报告走三级归属校验，是安全的双向（医生看全部 / 患者看本人）模型。
3. **完整工程闭环**：Docker 一键部署、GitHub Actions CI、54 项自动化测试、可查询的审计日志、软删除回收站、一键种子数据。

## 6. 常见追问与回答

| 追问 | 回答要点 |
|---|---|
| 为什么用三个存储？ | 各司其职：MySQL 业务数据（事务）、Neo4j 关系查询（疾病图天然适合图查询）、Milvus 向量相似度检索（RAG）。 |
| 降级怎么实现？ | 每层服务封装独立 client，启动/调用时探测，失败置 degraded 状态并返回降级文案；上层调用只关心"拿到了没有"。 |
| 患者怎么防越权？ | 手机号认领绑定 `user_id`；报告下载逐条校验 `report.record.patient.user_id == 当前用户`；他人/未绑定/匿名分别 403/403/401。 |
| 数据从哪来？ | Neo4j 内置 20 种疾病种子数据 + Milvus 18 条临床指南（种子脚本一键重建）；病历/患者为演示数据。 |
| 换个大模型行不行？ | 行。LLM 层走 openai SDK 统一接口，换 `LLM_BASE_URL` + `LLM_API_KEY` 即可，不影响上层。 |
| CI 为什么 MySQL/Neo4j 也用容器？ | GitHub Actions `services` 直接拉起，保证测试环境与生产一致，且不依赖 runner 预装。 |
| PDF 中文乱码怎么处理？ | reportlab 的 TTFont 不支持 CFF 字库（Noto CJK），统一用 `UnicodeCIDFont(STSong-Light)` 兜底。 |

## 7. 紧急故障预案

| 故障 | 处理 |
|---|---|
| LLM 不可用 | 诊断仍能出（降级到关键词+图谱），明确告知"当前为降级结果" |
| RAG 卡住 3-4 分钟 | 嵌入模型未缓存；答辩机已缓存，或启动加 `HF_HUB_OFFLINE=1` |
| Neo4j 图谱画不出 | 确认容器内 Neo4j healthy；`docker compose restart neo4j` |
| 前端 8080 打不开 | 本机 80 被占 → 前端映射 8080（.env `FRONTEND_PORT=8080`） |
| 演示数据乱了 | 重跑 seed 脚本一键重置（图谱+指南+患者） |
